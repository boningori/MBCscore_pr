# スタメン選択画面のチームタブ化

日付: 2026-07-27

## 背景

クォーター開始時のスタメン選択は、白チーム（teamA）→ 青チーム（teamB）の順に固定された2ステップ進行になっている。白の5名を確定しないと青の入力画面に進めない。

しかし現場では青チームから登録が始まることがある。その場合、青の情報が先に手元にあるのに白の入力が終わるまで登録できず、待ちが発生する。

## 目的

スタメン選択画面で、白と青のどちらからでも登録できるようにする。

## 現状の実装

| 箇所 | 内容 |
|---|---|
| `App.tsx` の `lineupTeamId` state | `'teamA' \| 'teamB'`。現在どちらのチームを選択中かを保持 |
| `App.tsx:188` | 試合開始時、常に `'teamA'` にセットして `quarterLineup` 画面へ |
| `App.tsx:656`（`handleQuarterEnd`） | Q終了時も常に `'teamA'` にリセット |
| `App.tsx:620`（`handleLineupConfirm`） | teamA 確定時は teamA だけ `SET_TEAMS` して `lineupTeamId` を `'teamB'` に。teamB 確定時に teamB を `SET_TEAMS` して `START_GAME` |
| `QuarterLineup.tsx` | 1チーム分の選択UI。選択状態・確定ボタン・戻るボタン・出場ルールの目安表示を持つ |
| `confirmLabel` prop | 1チーム目は「次へ（○○のスタメン）」、2チーム目は「Qx 開始」 |

白チーム＝teamA・青チーム＝teamB は `App.tsx:161` で固定されており、各 `Team` は `color: 'white' | 'blue'` を持つ。

## 設計

### 画面構成

```
┌──────────────────────────────────────┐
│ ← 戻る    [Q2]   スタメン選択          │
├──────────────────────────────────────┤
│ ┌──────────────┬──────────────┐      │  タブ（常時表示）
│ │ ● 白 ○○ミニバス │ ● 青 △△ミニバス │      │
│ │      5/5 ✓    │      3/5      │      │
│ └──────────────┴──────────────┘      │
├──────────────────────────────────────┤
│  （選択中チームの選手カード一覧）         │  中身は現状と同じ
│  前Q出場 / 3Q超・2Q未達チップ / 目安警告  │
├──────────────────────────────────────┤
│         [ Q2 開始 ]                   │  両チーム 5/5 で有効
│   青のスタメンが未選択です（3/5）         │  無効時のみ理由を表示
└──────────────────────────────────────┘
```

### 振る舞い

**タブ**
- 常に白が左・青が右で固定表示する。位置が入れ替わると誤タップの原因になるため、初期タブがどちらでも並び順は変えない。
- タブのラベルは `team.color` から決める（`'white'` → 「白」、`'blue'` → 「青」）。teamA/teamB という内部IDには依存しない。
- 各タブに選択状況を `3/5` の形式で表示し、5名揃ったタブには `✓` を付ける。入力中も相手チームの進捗が見える。
- タブを切り替えても、そのチームで選んだ選手は保持される。何度往復しても選び直しは不要。

**確定と開始**
- チーム個別の確定ボタンは置かない。5名選んだ時点でそのチームは「選択済み」として扱う。
- 画面下部のボタンは「開始」1つだけ。ラベルは Q1 が「試合開始」、Q2以降が「Qx 開始」、OTは「OT 開始」「OT2 開始」（現行の `quarterLabel` 生成ロジックを踏襲）。
- 開始ボタンは両チームとも5名揃うまで無効。無効な間はボタン下に未完了チームを示す文言を出す（例: 「青のスタメンが未選択です（3/5）」）。両チームとも未完了なら両方を列挙する。
- 出場ルールの目安（最低2Q・最大3Q・全員出場）は現状どおり非強制。警告が出ていても開始をブロックしない。

**初期タブ**
- `App` が `lineupTab` state で保持し、試合中は値を維持する。クォーターが変わってもリセットしない。
- 新規試合開始時は `'teamA'`（＝白）。ユーザーが一度青タブを開くと、以降のクォーターは青タブが開いた状態で始まる。
- 試合をリセット・新規開始したときは `'teamA'` に戻す。

**戻る**
- 「戻る」は1つだけ。試合前（`phase === 'setup'`）なら設定画面へ、試合中ならゲーム画面へ（クォーター終了の取り消しが可能）。
- 現行の「2チーム目から1チーム目のスタメン選択へ戻る」遷移は、タブで自由に行き来できるため不要になる。

### コンポーネント構造

現在 `QuarterLineup` が持っている「1チーム分の選択」の責務を2層に分ける。

**`QuarterLineup.tsx`（コンテナ）**

```ts
interface QuarterLineupProps {
    quarter: number;
    teamA: Team;
    teamB: Team;
    /** 初期表示タブ。省略時は 'teamA' */
    initialTab?: 'teamA' | 'teamB';
    /** タブ切替時に呼ばれる。App が次回の初期タブとして保持する */
    onTabChange?: (tab: 'teamA' | 'teamB') => void;
    /** 両チーム5名揃った状態で開始したときに1回だけ呼ばれる */
    onStart: (selected: { teamA: string[]; teamB: string[] }) => void;
    onBack?: () => void;
}
```

- 白・青**両方**の選択状態を `{ teamA: string[]; teamB: string[] }` として保持する。
- 各チームの初期選択は現行と同じロジック（`isOnCourt` かつ `fouls.length < 5` の選手）。
- クォーターが変わったら両チームの選択をリセットする。現行の `prevLineupKey` によるレンダー中の状態調整パターンを踏襲し、キーは `quarter` のみとする（チーム切替ではリセットしないため）。
- ヘッダー（戻る・クォーターバッジ・見出し）、タブバー、開始ボタン、無効理由の文言を描画する。

**`LineupTeamPanel.tsx`（新規・表示専用）**

```ts
interface LineupTeamPanelProps {
    quarter: number;
    players: Player[];
    selectedIds: string[];
    onToggle: (playerId: string) => void;
}
```

- 状態を持たない。選択件数表示、前Q出場の表示、選手カードグリッド、出場ルールのチップ（`3Q超` / `2Q未達`）、未出場バナー、目安の注記を描画する。
- 現行 `QuarterLineup.tsx` の96〜189行目の内容がほぼそのまま移る。5名上限のガード（`selectedIds.length < PLAYERS_ON_COURT`）はコンテナ側の `onToggle` 実装に置く。

**`QuarterLineup.css`** にタブバーのスタイルを追加する。タブは白／青のチームカラーが分かる配色にし、既存のチームカラー変数（`index.css` の白チーム／青チーム）を使う。

### App.tsx の変更

- `lineupTeamId` を `lineupTab` にリネームし、意味を「2ステップ進行の現在位置」から「表示中のタブ」に変える。
- `handleGameSetupComplete`（`App.tsx:188` 付近）: `setLineupTab('teamA')` にして Q1 の選択画面へ。
- `handleQuarterEnd`（`App.tsx:656`）: `lineupTab` をリセットしない（前回のタブを維持する）。
- `handleLineupConfirm` を `handleLineupStart(selected: { teamA: string[]; teamB: string[] })` に置き換える。
  - 白・青の両チームに `isOnCourt` と `quartersPlayed` を反映し、`SET_TEAMS` を**1回だけ**dispatchする。
  - その後 `setScreen('game')` し、`phase` が `'setup'` または `'quarterEnd'` なら `START_GAME` をdispatchする。
- `screen === 'quarterLineup'` のレンダリング（`App.tsx:919`）を新しい props に合わせる。`confirmLabel` の受け渡しは削除。

### 副次的な効果

現行は白を確定した時点で `SET_TEAMS` するため「白だけ確定済み」という中間状態が発生する。`gameFlowHandlers.ts:104` はクォーター終了を取り消す際にこの中間状態を打ち消す処理を持っている。

一括dispatchに変えることでこの中間状態自体が発生しなくなる。ただし既存の打ち消し処理は他のUndo経路の保険として**そのまま残す**（削除しない）。

### 変更しないもの

- 試合中の交代（`SubstitutionModal`）の挙動
- 白＝teamA・青＝teamB の固定割り当て
- 出場ルールの目安の判定ロジックと非強制の方針
- スコアシート出力、統計、その他の画面

## テスト

`QuarterLineup.test.tsx` は props 形状が変わるため書き換える。出場ルールの目安（チップ・未出場バナー）の検証内容は現行のケースを維持し、新しい props で組み直す。`confirmLabel` に関する2ケースは、開始ボタンのラベル検証（Q1「試合開始」／Q3「Q3 開始」）に置き換える。

追加するケース:

1. 青タブから先に5名選び、その後白タブで5名選ぶと開始できる（`onStart` が両チームのIDを含む1回の呼び出しで発火する）
2. タブを白→青→白と往復しても、白で選んだ選手が保持されている
3. 片方だけ5名のとき開始ボタンが無効で、未完了チーム名を含む文言が表示される
4. `initialTab='teamB'` を渡すと青タブが選択された状態で描画される
5. タブ切替時に `onTabChange` が新しいタブIDで呼ばれる

`LineupTeamPanel` は表示専用のため、単体テストは設けず `QuarterLineup` 経由で検証する。

## 完了条件

- 白・青どちらのタブからでもスタメンを登録でき、順序の制約がない
- 両チーム5名揃うまで開始できず、揃っていないチームが画面上で分かる
- 一度青タブを開いたら、以降のクォーターも青タブで開く
- `npm test` と `npm run lint` が通る
