# 複数人の一括交代 — 設計

- 日付: 2026-09-07
- ステータス: 設計承認済み（2026-09-07）
- 対象: `src/components/SubstitutionModal/`

## 背景

交代モーダルは1組ずつしか交代できない。コート(OUT)から1人、ベンチ(IN)から1人を選び「交代実行」を押す、を人数分繰り返す。

しかしバスケでは、タイムアウト明けやクォーター間に**複数人をまとめて替える**のが普通で、コーチからも「4番と5番を下げて、9番と10番を入れて」とまとめて指示が来る。いまの作りだと、その指示を1組ずつに分解して4回タップし直すことになる。試合が止まっている短い時間に間に合わない。

（モーダルを閉じない・連続交代できるという既存の工夫は、この問題への部分的な対処だった。`SubstitutionModal.tsx` の `handleConfirm` のコメントに経緯がある。）

## 調査で分かった前提

**交代は履歴に残らない。** `handleSubstitutePlayer`（`src/context/reducers/gameFlowHandlers.ts`）が書き換えるのは2つだけ。

- 入る選手: `isOnCourt: true`、`quartersPlayed[今のQ]` を `sub`（既に `starter`/`sub` なら `both`）に
- 出る選手: `isOnCourt: false`

`scoreHistory` / `statHistory` / `foulHistory` に相当する「交代履歴」は `Game` 型に存在せず、スコアシートにも出力されない。

したがって**「誰が誰と替わったか」という組み合わせはどこにも保存されない**。残るのは「誰がこのQに出場したか」だけ。一括交代をどう組んでも、結果の状態は同じになる。組み合わせは画面上の見え方の問題に過ぎない。

## スコープ

### やること

- コート(OUT)・ベンチ(IN)とも複数選択にする
- 同数のときだけ一括で交代を実行する
- 選手の表示をコートネーム優先にする（アプリ全体の書き方に揃える）
- スマホでベンチも2列表示にして、一度に見える人数を増やす

### やらないこと（YAGNI・今回のスコープ外）

- **組み合わせの記録**。保存先が無く、スコアシートにも出ない
- ペアの明示的な指定・並べ替え。上記のとおり結果に影響しない
- 交代の取り消し。既存にも無く、この変更で新しく必要になるものでもない
- タブレット・PC幅のレイアウト変更。1列表示のまま（元から溢れておらず、変える理由がない）
- `SUBSTITUTE_PLAYER` アクションと `App.tsx` の改修。既存のまま人数分ディスパッチする

## 設計判断（ユーザー合意事項）

| 論点 | 決定 | 理由 |
|---|---|---|
| 組み合わせの見せ方 | **集団として見せる**（`#4 #5 #6 ⇄ #9 #10 #11`） | 組み合わせは保存されないので、ペアを見せるとタップ順の間違いが「ずれ」に見えるだけで、実態は変わらない |
| 人数が違うとき | **実行させない**（ボタンを押せなくする） | コート上は5人固定。数が違うと成立しない。判断の余地がない |
| 1組だけのときの見た目 | 今までどおり。ボタンも `交代実行` のまま | 既存の使い方を変えない。ラベルを変えると既存テストの前提も崩れる |
| ディスパッチ | 背番号順に組を作り、既存アクションを人数分 | 1組ずつ送ればコート上が常に5人に保たれる。reducer を触らずに済む |
| スマホのベンチ | **2列表示**にする | 複数選択には一覧性が要る。実測で見える人数が 2.7人 → 5.6人 |

## 画面と操作

### 選択

両方の一覧を複数選択にする。カードをもう一度タップすると外れる。

見出しに選択数を出す（`コート (OUT)　2人選択`）。スマホではベンチをスクロールして戻ってきたときに、いま何人選んだかが分からなくなるため。

**誤タップに対して安全な作りになる。** いまはタップが単一選択で、#4 を選んだあと #5 を押すと選択が移る。変更後は両方選ばれた状態になるが、そのときベンチ側と数が合わなくなるので**ボタンが押せなくなるだけ**で、意図しない交代は実行されない。

### 実行の条件

`OUT ≥ 1` かつ `OUT の人数 === IN の人数` のときだけ「交代実行」が押せる。

押せないときは理由を出す。文言は数の食い違いを名指しする:

- 両方0: `コートとベンチから同じ人数ずつ選んでください`
- 片方0: `ベンチから2人選んでください`（コートだけ2人選んでいる場合）
- 数が違う: `コート3人・ベンチ2人を選んでいます。同じ人数にしてください`

### 実行

選択した両方を背番号順（`comparePlayerNumbers`）に並べ、先頭から組にして `onSubstitute(playerInId, playerOutId)` を人数分呼ぶ。`onSubstitute` の型は変えない。

`App.tsx` の `handleSubstitute` はそのまま。1回の呼び出しにつき `SUBSTITUTE_PLAYER` が1回ディスパッチされる。React 19 は同一ハンドラ内のディスパッチをまとめて処理するので再描画は1回。

### 実行後の表示

既存の `.substitution-note`（貼り付いたフッター内）に結果を出す。枠の高さは既存のまま保つ（`min-height: 3rem`。ボタンが動いて指が「完了」を踏むのを防ぐ既存の工夫）。

- 1組: `#4 ホーム1 → #9 ホーム6` / `交代しました`（**現状のまま**）
- 複数: `#4 #5 #6 ⇄ #9 #10 #11` / `3人交代しました`

複数のときに氏名を入れないのは、交代を**背番号で認識する**ため。番号だけで人は特定でき、氏名まで並べると375px幅の枠に収まらない。1組のときは枠に余裕があるので、確認しやすいよう既存どおり氏名も出す。

モーダルは閉じない。選択だけ解除して次の交代に進める（既存の連続交代の作りを維持）。`doneCount` は交代した**人数**ではなく**実行回数**を数える既存の意味を保ち、案内は `（この画面で2件）` のまま。

## カードに載せる情報

### コートネーム優先（幅を問わず）

交代は背番号で認識する。氏名（フルネーム）は要らず、必要なのは**コートネーム**と**退場バッジ**。

`courtName || name` はこのアプリ全体の既定の書き方で、`Scoreboard` `TeamPanel` `ActionHistory` `FoulInputFlow` `EditActionModal` `PendingActionPanel` `useFoulOutNotice` `App.tsx` がすべてこの形。**素の `name` を出しているのは `SubstitutionModal` だけ**で、こちらが例外になっていた。揃える。

フォールバックは外さない。`courtName` は `MyTeamManager`（マイチーム）でしか設定できず、対戦相手の選手には存在しない。コートネームが無いときに何も出さないと、番号だけのカードが並ぶことになる。

実行後の案内（`.substitution-note`）の1組表示も同じ規則にする。

### 得点・出場Qはスマホだけ落とす

| 項目 | スマホ（〜600px） | タブレット・PC（601px〜） |
|---|---|---|
| 背番号 | 出す | 出す |
| コートネーム（無ければ氏名） | 出す | 出す |
| 退場バッジ | 出す | 出す |
| 得点（`0pts`・コート側） | **消す** | 出す |
| 出場Q（`Q: 1,2`・ベンチ側） | **消す** | 出す |

タブレットは幅に余裕があり、出場Qは「最低2Q・最大3Q・全員出場」の目安を見るのに使える。狭いスマホでだけ落とす。

（コート側の得点は `2026-09-06` の2列化で既にスマホでは消してある。ベンチ側の出場Qを今回そろえる。）

## スマホのベンチ2列表示

`@media (max-width: 600px)` の中だけを変える。コート(OUT)は既に2列（`2026-09-06` の変更）。

**識別子は背番号。氏名は補助。** 交代は番号で認識するので、狭いところで削るのは氏名であって番号ではない。この原則で詰める。

- **背番号の文字は大きいまま**（`--font-size-xl`）。ただし `min-width: 50px` は2列では外す。1列で数字の桁を揃えるための指定で、2列では23pxの無駄になる（実測で氏名の幅が 61px → 84px に増える）
- **名前は1行に切り詰める**（`white-space: nowrap` ＋ `text-overflow: ellipsis` ＋ `min-width: 0`）。折り返させない。番号の位置が行ごとに動くと、番号で拾う読み方が成立しない。コートネームは短いので実際に切れるのは、コートネームが未設定でフルネームに落ちた選手だけになる
- 名前の文字は `--font-size-sm` に落とす
- **退場バッジは残す**。失格した選手をIN候補から外さない代わりに併記して見落としを防ぐという既存方針（`SubstitutionModal.tsx` のコメント）の要。消すと方針が崩れる

**グリッドの列は `minmax(0, 1fr)` にする。** `1fr` は `minmax(auto, 1fr)` と同義で、最小幅が中身で決まるため、長い氏名がカードごとモーダルの外へ押し出される。実測で `佐々木健太郎` を入れたところ実際に枠外へ飛び出した。

これは**既に入れたコート(OUT)の2列表示にも同じ問題がある**（`2026-09-06` の変更。短い氏名でしか試しておらず気づかなかった）。今回あわせて直す。

実測（375×812・ベンチ10人・長い氏名を入れた状態）:

| | 1列（現状） | 2列 |
|---|---|---|
| 一度に見える人数 | 2.7人 | 5.6人 |
| カード幅 | 311px | 約160px |
| 氏名に使える幅 | 十分 | 約84px（`--font-size-sm` で5〜6文字） |
| `山田花子` `ヴィクトリア` `あきら` | 全部出る | 全部出る |
| `佐々木健太郎`（コートネーム未設定の例） | 全部出る | `佐々木健…` と切れる |
| カードの高さ | 50px | 50px（折り返さないので変わらない） |

コートネームはニックネームなので通常は短く、切り詰めが起きるのは未設定でフルネームに落ちた選手だけ。

## テスト

### `SubstitutionModal`（既存 `SubstitutionModal.test.tsx` に追加）

- コート・ベンチとも複数選択でき、もう一度タップで外れること
- 人数が違うあいだは「交代実行」が押せないこと（コート2・ベンチ1、コート1・ベンチ2の両方向）
- 同数にすると押せるようになること
- 3人を選んで実行すると `onSubstitute` が**3回**、背番号順の組で呼ばれること
- 実行後に選択が解除され、モーダルは閉じないこと
- 実行後の案内が、1組では既存の `#4 ホーム1 → #9 ホーム6` のままで、複数では `#4 #5 ⇄ #9 #10` の形になること
- 見出しに選択数が出ること
- コートネームがある選手はコートネームが出て、無い選手は氏名にフォールバックすること（両方の一覧で）
- **既存の1組交代のテストが全て通ること**（`交代実行` のラベル、`onSubstitute('out', 'onCourt')` の呼ばれ方）

### App 統合（新規 `src/App.bulkSubstitution.test.tsx`）

既存の App レベルのテストに交代そのものを主題にしたファイルは無い（`App.benchTechOverflow.test.tsx` などは交代を経由するだけ）。新しく1本作る。

- 3人を一括交代すると、コート上の5人が正しく入れ替わること
- 入った選手の `quartersPlayed[今のQ]` が `sub`（スタメンだった選手が戻る場合は `both`）になること

## 想定される失敗と、その扱い

| 起きること | 扱い |
|---|---|
| 単一選択のつもりで2人目を押してしまう | 数が合わなくなりボタンが押せなくなるだけ。意図しない交代は起きない |
| 選んだ人数を忘れる（スマホでスクロール後） | 見出しに選択数を出す。2列化で一覧性も上げる |
| 長い氏名が2列に収まらない | 番号は削らず氏名を `佐々木健…` と切り詰める。交代は背番号で認識するため |
| 長い氏名がカードごと枠外へ飛び出す | 列を `minmax(0, 1fr)` にする。コート側の既存の2列表示も同時に直す |
| 出場Qがスマホのベンチで見えなくなる | タブレット・PCでは残す。スマホでは幅が無く、出場ルールの目安はスタメン選択画面も担っている |
| コートネームが未設定の選手が並ぶ（対戦相手など） | 氏名にフォールバックする。アプリ全体と同じ `courtName \|\| name` |
