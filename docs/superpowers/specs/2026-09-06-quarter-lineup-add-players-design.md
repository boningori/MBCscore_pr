# スタメン選択画面からの選手追加（番号グリッド一括登録） — 設計

- 日付: 2026-09-06
- ステータス: 設計承認済み（2026-09-06）
- 対象: `src/components/QuarterLineup/`, `src/components/TeamShared/playerLimit.ts`, `src/App.tsx`

## 背景

Q開始時のスタメン選択画面（`QuarterLineup`）は、登録済みの選手カードから5人をタップして選ぶ画面である。ここで選べるのは**試合設定で登録した選手だけ**で、名簿から漏れた選手を足す手段がない。

漏れは実際に起きる。遅れて会場に着いた選手、当日にメンバーが入れ替わった相手チーム、そもそも名簿を貰えずに始まる練習試合。いま漏れに気づいた記録者が取れる手は2つしかない。

1. 一度スタメン選択を抜けてゲーム画面へ行き、交代モーダルの「＋ 選手を追加」（`SubstitutionModal`）で足す
2. 試合設定まで戻る（試合中は戻れない）

1 は Q開始前の段階では回り道が長く、そもそも交代モーダルは「いま出ている選手と入れ替える」画面なので、スタメンを決める途中に開く場所ではない。**気づいた場所で足せない**のが問題。

さらに、名簿ごと無い相手チームでは1人ずつフォームに打ち込むことになる。対戦チーム管理（`OpponentManager`）には番号をタップするだけで登録できる「番号一括選択」パネルがあるのに、試合が始まってからは使えない。

## スコープ

### やること

- スタメン選択画面に「+ 選手を追加」の入口を置く
- 番号グリッド（0〜99＋00）で複数の背番号をまとめて選び、氏名を任意で添えて一括登録する追加パネルを作る
- 15人（公式様式の選手欄）を超える場合に、**誰が様式から外れるか**を確定前に名指しで伝える
- 複数人追加に対応した溢れ判定 `findOverflowPlayers` を `playerLimit.ts` に足し、既存の単数版をその上に載せ替える

### やらないこと（YAGNI・今回のスコープ外）

- **追加した選手の取り消し・削除**。削除アクション自体がアプリに存在せず（`ADD_PLAYER_TO_TEAM` の対になる action は無い）、記録済みの選手まで消せる口を開けるのは別の判断が要る。確定前の2段構え（下記）で誤登録を防ぐ方針とする
- 試合中の選手名の変更。いまも手段が無く、この機能で新しく必要になるものでもない
- `OpponentManager` / `OpponentSelect` の番号グリッドのリファクタリング。CSSは共有するが、振る舞いが違う（後述）ため共通コンポーネント化はしない
- 追加した選手の自動選択（スタメン5人への自動投入）
- OCR・写真読込からの追加（対戦チーム管理側の機能のまま）

## 設計判断（ユーザー合意事項）

| 論点 | 決定 | 理由 |
|---|---|---|
| 「番号一括選択」の意味 | 5人の**選択**ではなく、漏れた選手の**登録**。登録後の5人選びは従来通り | 利用者の意図がスタメン選択の効率化ではなく名簿の補完だったため |
| 入力方法 | 対戦チーム管理と同じ番号グリッド（0〜99＋00） | 既に使い慣れたUIがあり、名簿ごと無い相手チームでも番号だけは分かる |
| 氏名 | 確定リストで**任意入力**。空欄なら `選手7` を自動生成 | 試合中に名前を直す手段が無く、付いた名前がスコアシートにそのまま載る。急ぐなら飛ばせて、分かるなら入れられる形にする |
| 登録済み番号のタップ | **押せない**（「登録済み」表示・`disabled`） | 対戦チーム管理はタップで削除できるトグルだが、試合中は削除アクションが存在しない。同じ見た目で消せるように見せると嘘になる |
| 確定のタイミング | グリッドで選んだ時点では登録せず、**「◯人を追加」で一括確定** | 101マスの誤タップが取り消せない登録に直結するのを防ぐ。取り消し機能を作らずに誤登録を防げる最小の作り |
| 追加した選手の扱い | 自動選択しない。番号順にカードが増えるだけ | 5人の枠を勝手に埋めると意図しない出場記録（`quartersPlayed`）になる |
| 15人超過 | **止めない**。誰が外れるかを確定前に名指しで出す | 練習試合では人数が読めないまま始まる。止めると記録そのものができない。退場者を一覧から外さないのと同じ方針 |

## 画面と操作

### 入口

`LineupTeamPanel` の選手カード一覧（`.player-selection-grid`）の直下、出場ルールの案内（`.quarter-rule-hint`）の上に「**+ 選手を追加**」ボタンを置く。「あの子のカードが無い」と気づく場所の直下に置くための位置。

対象チームは**そのとき開いているタブのチーム**（白 = `teamA` / 青 = `teamB`）。パネルの見出しにチーム名と色を出して取り違えを防ぐ。

### 追加パネル `AddPlayersPanel`

`Modal` を土台にする（Escape・端末の戻る操作・フォーカストラップ・フォーカス復帰が `modalStack` 経由で揃うため）。中身は2段。

**1. 番号グリッド**

`src/styles/number-grid.css` をそのまま流用し、見た目は対戦チーム管理と揃える。0〜99 と 00（内部表現 `DOUBLE_ZERO_INTERNAL = 100`）の101マスを、`OpponentManager` と同じ並び（00は99の後）で描く。

- 未登録の番号: タップで選択/解除。選択は**パネル内の下書き**で、まだ登録されない
- 登録済みの番号: `disabled` + 「登録済み」が分かる装飾。押しても何も起きない
- 下書きで選択中の番号: 選択状態の装飾（`.selected`）

**2. 確定リスト**

選ばれた番号を背番号順（`sortPlayersByNumber` と同じ順序）に並べ、各行に氏名の任意入力欄を出す。行から番号を外す操作もここでできる（グリッドをスクロールして戻らなくて済むように）。

**フッター**

- 「キャンセル」: 何も登録せずに閉じる
- 「**◯人を追加**」: 選択が0件なら `disabled`

### 15人あふれの案内

確定リストの下に、追加後に公式様式（15人分）から外れる選手がいる場合だけ表示する。文言は `SubstitutionModal` の既存の案内と揃える。

- 外れるのが追加する選手自身の場合: 「スコアシートの選手欄は15人分です。#16 は印刷・出力に載りません（記録は残ります）。」
- 外れるのが既存選手の場合: 「スコアシートの選手欄は15人分です。追加すると #24 山田 が印刷・出力に載らなくなります（記録は残ります）。」
- 複数人が外れる場合: 外れる選手を全員列挙する

名簿は背番号順に並び（`handleAddPlayerToTeam` の `sortPlayersByNumber`）、スコアシートは先頭15人しか描かない（`RunningScoresheet` の `players.slice(0, 15)`）。**若い番号を足すと番号の大きい既存選手が押し出される**ため、「追加する人が載らない」とは限らない。ここを取り違えると、得点を記録済みの選手が黙って様式から消える。

## データの流れ

```
LineupTeamPanel「+ 選手を追加」
        ↓ (open)
AddPlayersPanel  … 下書き状態はパネル内のローカル state
        ↓ onSubmit([{number, name}, ...])
QuarterLineup    … 名簿の状態は持たない。onAddPlayers(teamId, players) を上へ投げるだけ
        ↓
App.tsx          … 選手ごとに dispatch({ type: 'ADD_PLAYER_TO_TEAM', payload: { teamId, number, name } })
        ↓
GameContext      … reducer は無改修
        ↓ state.teamA / state.teamB
QuarterLineup    … props 経由でカードが増える
```

`QuarterLineup` は名簿を state に持たず props をそのまま描いているため、追加後の再描画で自然にカードが増える。既存の `selected`（選択中の5人）は選手IDの配列で、クォーターが変わったときだけリセットされる。**追加はクォーターを変えないので、選択中の5人は消えない**。

`ADD_PLAYER_TO_TEAM` は既存アクションをそのまま使う。1人ずつ dispatch するが、React 19 は同一ハンドラ内の dispatch をまとめて処理するため再描画は1回で済む。

### `playerLimit.ts` の変更

既存の `findOverflowPlayer(players, newPlayer)` は1人追加専用で、`ordered[15]` を返す。複数人版を足し、単数版はその薄いラッパにする。

```ts
/** 追加したときに公式様式（15人分）から外れる選手を全て返す。溢れないなら空配列 */
export function findOverflowPlayers(
    players: readonly NumberedPlayer[],
    newPlayers: readonly NumberedPlayer[],
): NumberedPlayer[] {
    const ordered = sortPlayersByNumber([...players, ...newPlayers]);
    return ordered.slice(MAX_PLAYERS_PER_TEAM);
}

export function findOverflowPlayer(
    players: readonly NumberedPlayer[],
    newPlayer: NumberedPlayer,
): NumberedPlayer | null {
    return findOverflowPlayers(players, [newPlayer])[0] ?? null;
}
```

並べ替えを別実装で書くと「誰が外れるか」の案内と実際の結果がずれるため、判定は1か所に集約する。既存の単数版の戻り値・呼び出し側（`SubstitutionModal`）は変えない。

## 入力の検証

- 背番号: グリッドからしか選べないため、範囲外（`isValidPlayerNumber` が偽）の値は入らない
- 重複: 登録済みの番号は `disabled` なので選べない。二重登録は起きない
- 氏名: 空欄・空白のみなら `選手${formatPlayerNumber(number)}` を自動生成（`SubstitutionModal` と同じ規則）
- 人数上限: 15人を超えても**止めない**。上記の案内を出すだけ

## テスト

### `AddPlayersPanel`（新規 `AddPlayersPanel.test.tsx`）

- 登録済みの背番号のボタンが `disabled` であること
- 未登録の番号をタップすると確定リストに並び、もう一度タップで外れること
- 確定すると `onSubmit` が**背番号順**の配列で1回だけ呼ばれること
- 氏名を空欄にした行が `選手7` の形で渡ること／入力した氏名がそのまま渡ること
- キャンセルで `onSubmit` が呼ばれないこと
- 選択0件では確定ボタンが `disabled` であること
- 15人を超える追加で、外れる選手の背番号と氏名が案内に出ること（既存選手が押し出される場合を含む）

### `QuarterLineup`（既存 `QuarterLineup.test.tsx` に追加）

- 「+ 選手を追加」で開いたパネルの対象が、**開いているタブのチーム**であること
- 追加後にそのチームの選手カードが増えること
- **追加しても選択中の5人が解除されないこと**
- 追加した選手が自動選択されないこと

### `playerLimit`（既存 `overflowPlayer.test.ts` に追加）

- `findOverflowPlayers` が複数人追加で外れる選手を全て返すこと
- 若い番号を複数足したとき、番号の大きい既存選手が押し出されること
- 溢れないときに空配列を返すこと
- 既存の `findOverflowPlayer` の戻り値が変わらないこと

### App 統合（既存 `App.quarterLineup.test.tsx` に追加）

- スタメン選択画面から追加した選手が、**対象チームだけ**に入ること
- 追加した選手の `quartersPlayed` が空（未出場）で、`isOnCourt` が偽であること

## 想定される失敗と、その扱い

| 起きること | 扱い |
|---|---|
| 101マスの誤タップ | 確定するまで登録されない。確定リストから外せる |
| 間違えた番号で確定してしまった | 取り消せない（スコープ外）。確定リストで番号と氏名を見せてから確定する2段構えで防ぐ |
| 15人を超えてスコアシートに載らない選手が出る | 止めずに、誰が外れるかを確定前に名指しで案内する。記録自体は残る |
| 氏名を入れずに確定した | `選手7` としてスコアシートに載る。試合中は直せないため、確定リストに氏名欄を出して入力機会を作る |
| 相手チームのタブを開いたまま自チームの選手を足す | パネル見出しにチーム名と色を出す |
