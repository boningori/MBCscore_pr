# 音声メモ：読みながら入力できるようにする — 設計

- 日付: 2026-08-25
- ステータス: 設計承認済み（2026-08-25）
- 前提: [2026-08-24-voice-memo-design.md](2026-08-24-voice-memo-design.md)（v1.5.0 でリリース済み）

## 背景

v1.5.0 をリリースした直後、実際に使った利用者から2点の指摘があった。どちらも実害がある。

### 問題1: メモの文字が読めない

一覧パネルの本文が「薄すぎる」。実測すると薄いのではなく、**カード背景 `rgb(255,255,255)` の上に本文 `rgb(248,250,252)`** で、コントラスト比は約 1.03:1。WCAG AA の 4.5:1 に遠く及ばず、事実上の白地に白文字だった。

原因は `src/components/VoiceMemo/VoiceMemo.css` が**このプロジェクトに存在しないCSS変数**を参照していたこと。

| CSSが参照していた名前 | このプロジェクトの実際の名前 |
|---|---|
| `--color-surface` | `--bg-card` (#1e293b) |
| `--color-text` | `--text-primary` (#f8fafc) |
| `--color-text-muted` | `--text-muted` (#8695ad) |
| `--color-border` | `--border` (#334155) |
| `--color-danger` | `--danger` (#dc2626) |

未定義の変数はフォールバック値（`#fff` / `#666` / `#ccc` など明るいテーマ前提の色）に落ちる。このアプリは `--bg-primary: #0f172a` のダークテーマなので、暗い画面に白いカードが乗り、本文は色指定が無いためアプリのほぼ白い文字色を継承した。

CSSだけを読むとフォールバックは一見もっともらしく、実装レビューでも検出できなかった。**描画結果の色を測る検証が無かった**ことが見逃した理由。

### 問題2: メモを見ながら入力できない

一覧がモーダルなので、開くと画面全体を覆う。読む → 閉じる → 入力、を繰り返すことになる。

しかし1回の押下で吹き込む内容は「青5シュートミス、青6リバウンド、青6アシスト、青4シュート成功」のように**1件のメモに複数の出来事が入る**。閉じた瞬間に覚え直しになり、覚えていられないから吹き込んだという目的を最後の一歩で潰していた。

設計時の「常に見えている必要はなく、確認したい時に確認できればOK」という要件をモーダルとして実装したが、実際の「確認したい時」は**入力している最中**だった。要件の取り違え。

## スコープ

### やること
- `VoiceMemo.css` のCSS変数を実在するトークンに直す
- スコアボードの上にフローティングする「メモ帯」を追加し、入力ボタンを動かさずに読めるようにする
- 帯は1件ずつ消化する。「済にする」で消えて次の1件へ進み、直後なら元に戻せる
- 「たたむ」で、メモを残したまま引っ込める
- 既存の一覧モーダルは残す（全件を読む・再送する・個別に消すための入口）

### やらないこと（YAGNI・今回のスコープ外）
- 録音・文字起こし・プライバシー・寿命まわりの変更（v1.5.0 のまま）
- 文字起こし結果からスタッツへの自動反映
- メモの「済」状態を永続化すること（済＝削除。状態は増やさない）
- 帯から任意のメモへ飛ぶ機能（常に最古の1件。飛ばしたいときは一覧から消す）
- 帯のドラッグ移動・リサイズ

## 設計判断（ユーザー合意事項）

| 論点 | 決定 | 理由 |
|---|---|---|
| 消化の単位 | 1件ずつ。済にすると次へ | 吹き込む単位（1回）と入力する単位（複数回）がずれているため、片付くまで消えないほうが実態に合う |
| 「済」の意味 | 一覧から削除。直後だけ元に戻せる | 入力後はスタッツ側が正。残ると二重入力の元になる。音声は保持していないので誤タップだけUndoで守る |
| 表示方法 | 自分で開く（自動表示しない） | 記録中にレイアウトが指の下で動くと誤入力になる。開く瞬間を利用者が選べるようにする |
| 配置 | スコアボードの上にフローティング | レイアウトを一切動かさず、入力ボタンとの距離も最短。中央列に挟む案は入力ボタンを押し下げる |
| 退避手段 | 「済」とは別に「たたむ」を用意 | スコアボードにはクォーター操作ボタンが載っている。覆っている間そこへ手を伸ばすのに、メモを捨てる以外の出口が要る |
| Undoの置き場所 | App の専用枠（既存の `UndoSnackbar` は使わない） | App の `undoInfo` は得点・スタッツ取り消しと共用の1枠。相乗りすると「済」を押した瞬間に得点の取り消しが消える。試合中はそちらが重要。帯の内部に置けないのは、最後の1件を済にすると帯ごとアンマウントされ Undo が出る前に消えるため |

## 構成

### 変更するファイル

| ファイル | 変更内容 |
|---|---|
| `src/components/VoiceMemo/VoiceMemo.css` | CSS変数を実在するトークンへ。帯のスタイルを追加 |
| `src/components/VoiceMemo/VoiceMemoStrip.tsx` | **新規**。フローティングする1件表示の帯 |
| `src/components/VoiceMemo/VoiceMemoStrip.test.tsx` | **新規** |
| `src/components/VoiceMemo/index.ts` | `VoiceMemoStrip` を追加 |
| `src/App.tsx` | ヘッダーの「一覧」ボタンを帯の開閉に変更。中央列に帯を描画 |
| `src/App.css` | 中央列を `position: relative` にする（帯の基準） |
| `src/hooks/useVoiceMemo.ts` | `restoreMemo` を追加（Undo 用） |
| `src/hooks/useVoiceMemo.test.tsx` | `restoreMemo` のテスト |

`useVoiceMemo` には Undo のための復帰手段だけ足す。

```ts
/** 済にしたメモを一覧へ戻す。createdAt を保つので元の並び位置に復帰する */
restoreMemo: (memo: VoiceMemo) => void;
```

現在のフックには「消す」（`removeMemoById`）はあるが「戻す」が無いため、これが無いと Undo が成立しない。

**注意:** `removeMemoById` は再送用の音声Blobも同時に捨てる。`failed` のメモを済にしてから戻した場合、
メモ自体は戻るが再送はできなくなる（`canRetry` が false になる）。音声を残さない設計の帰結であり、
これは許容する。戻したいのは「読むための文字」であって、再送の機会ではない。

### VoiceMemoStrip の責務

```ts
export interface VoiceMemoStripProps {
    /** 表示するメモ（一覧の最古の1件）。無ければ帯自体を描画しない */
    memo: VoiceMemo;
    /** 全件数。「1件目 / 全2件」の表示に使う */
    total: number;
    /** そのメモを再送できるか */
    canRetry: boolean;
    onRetry: (id: string) => void;
    /** 済にする（＝削除）。Undo の猶予は App 側が持つ */
    onDone: (id: string) => void;
    /** 猶予中に「元に戻す」対象として表示するメモ。null なら通常表示 */
    undoMemo: VoiceMemo | null;
    /** 「元に戻す」が押された */
    onUndo: () => void;
    /** たたむ（メモは残す） */
    onCollapse: () => void;
    /** 一覧モーダルを開く */
    onOpenList: () => void;
}
```

表示するメモの状態ごとに中身を変える。

| メモの状態 | 帯の中身 | 操作 |
|---|---|---|
| `sending` | ⏳ 文字起こし中… | たたむ / 済にする / 一覧 |
| `done` | 文字起こし本文 | たたむ / 済にする / 一覧 |
| `failed` | ⚠️ 理由 | たたむ / 済にする / 一覧 / 再送（`canRetry` のとき） |

`sending` でも「済にする」を出すのは、待つ気が無いメモを片付けられなくなるのを避けるため。

### Undo の扱い

「済にする」を押したら、帯は**そのメモを消したうえで、同じ場所に数秒だけ「済にしました ／ 元に戻す」を表示**する。時間切れか次の操作で消え、次のメモへ進む。

App の `undoInfo`（得点・スタッツ用）には触らない。Undo が帯の中にあることで、利用者の視線が既にある場所に出る利点もある。

元に戻したメモは `createdAt` を保持したまま一覧へ戻るので、並び順は元の位置に復帰する。

**Undo の状態は `App.tsx` が持つ。**帯の内部に置くと、最後の1件を済にした瞬間に
`memos.length > 0` が偽になって帯ごとアンマウントされ、「元に戻す」が出る前に消えてしまう。
App が専用の枠（`voiceMemoUndo`）を1つ持ち、帯はそれを props で受け取って表示するだけにする。

得点・スタッツ用の `undoInfo` とは別枠にする点は変わらない。共用しないことが目的であって、
置き場所が App であること自体は問題にならない。

帯の描画条件も `memos.length > 0 || voiceMemoUndo !== null` になる。
「たたむ」を押すと猶予は破棄される（戻せなくなる）。たたむのは席を外すような操作ではなく、
直後に別の場所を触るための退避なので、そこまで持ち越す必要はないと判断した。

### 開閉の状態

`App.tsx` が `showVoiceMemoStrip` を持つ。ヘッダーの `📝` ボタンで開閉する。

- 帯を開く条件: `isFeatureEnabled` かつ `showVoiceMemoStrip` かつ（`memos.length > 0` または Undo 猶予中）
- 最後の1件を済にしたら自動的に閉じる（`memos.length === 0` で描画されない）
- 「たたむ」は `showVoiceMemoStrip` を false にするだけ。メモは残る
- ヘッダーのボタンは件数を出す（現行の「📝 一覧 N」を「📝 メモ N」に改める。一覧モーダルへは帯の中の「一覧」から行く）

### 配置の実装

中央列（`.center-column`）を `position: relative` にし、帯を `position: absolute; top: 0; left: 0; right: 0;` で重ねる。スコアボードだけを覆い、その下の入力ボタンには一切かからない。

TF・タイムアウトは左右のチームパネル側にあるため隠れない。隠れるのはスコア表示とクォーター操作ボタン。

## コントラストの修正

`VoiceMemo.css` の変数を差し替える。フォールバック値も、万一トークンが消えたときにダーク側へ落ちる値にする（`var(--bg-card, #1e293b)` のように）。

修正後は**実際に描画された色を測って検証する**。CSSの記述を読むだけでは今回の見落としを繰り返す。本文とカード背景のコントラスト比が 4.5:1 以上であることをテストで確認する。

## テスト

- `VoiceMemo.css` が参照するCSS変数がすべて `src/index.css` に定義されていること（今回の再発防止。CSSを文字列として読み、`var(--…)` を抽出して照合する）
- 本文とカード背景のコントラスト比が 4.5:1 以上（計算した比を検証する）
- 帯: 3つの状態それぞれの表示、`canRetry` による再送ボタンの出し分け
- 帯: 「済にする」で `onDone` が正しいIDで呼ばれ、Undo が出ること
- 帯: `undoMemo` が渡ると「済にしました ／ 元に戻す」表示になること
- 帯: 「元に戻す」で `onUndo` が呼ばれること
- 最後の1件を済にしても、猶予のあいだ帯が消えないこと
- フック: `restoreMemo` が `createdAt` の順で元の位置へ戻すこと
- フック: `failed` のメモを消して戻すと `canRetry` が false になること
- 帯: 「たたむ」ではメモが消えないこと
- 帯: 最後の1件を済にしたら描画されなくなること
- 帯を開いても入力ボタンの位置が変わらないこと（フローティングであることの確認）

既存の vitest 構成に合わせる。jest-dom は導入していないので素のDOMプロパティで検証する。
